# kaggleComp

Shared repo for the Kaggle Titanic competition (CS 4320).

## Course requirements

See [Course project requirements](docs/COURSE_REQUIREMENTS.md) for the Kaggle milestones, grading weights and deadlines, AI vibe coding project deliverables, and shared presentation guidance. The vibe coding project must solve a separate machine learning problem and cannot be another Kaggle competition.

## Data

- `train.csv` - 891 labeled passengers. Target column is `Survived` (0/1).
  Features: `PassengerId, Pclass, Name, Sex, Age, SibSp, Parch, Ticket, Fare, Cabin, Embarked`.
- `test.csv` - 418 unlabeled passengers used to generate the submission.

## Notebook

- [titanic.ipynb](titanic.ipynb) - final Kaggle report with embedded score evidence, inline helper code, data checks, EDA, five-fold development cross-validation, controlled experiments, consolidated results, conclusions, and limitations.
- Checkpoints 1 and 2 have submission evidence: dummy 0.62200, logistic regression 0.76794, random forest 0.77751. These scores belong to the original uploads, not predictions regenerated by the cleaned pipelines.
- [titanic_features.py](titanic_features.py), [titanic_models.py](titanic_models.py), and [titanic_inspection.py](titanic_inspection.py) contain the tested source versions of feature engineering, model pipelines, submission checks, and grouped permutation inspection. Matching definitions are embedded in the final notebook so it runs without these modules.
- [Experiment record](docs/EXPERIMENTS.md) tracks six confirmed non-dummy uploads. Submission 6 has the highest recorded Kaggle score, **0.77990**. The six-submission minimum is met.
- Submission 4 compared nine random forest depth/leaf settings. The existing depth-5/leaf-1 control won at 0.8329 mean CV accuracy; the selected predictions are identical to the cleaned control. Its uploaded file, `submission_04_random_forest_tuned.csv`, scored **0.77511** on November 14; [score evidence](assets/submission_04_score.png) is saved.
- Submission 5 scored **0.77033** on November 14 ([score evidence](assets/submission_05_score.png)): logistic regression selected C=10 with no class weighting from ten configurations. Mean CV accuracy is 0.8231 versus the cleaned control's 0.8216; only one test label changes. The notebook adds precision, recall, F1, ROC-AUC, average precision, confusion matrices, curves, and timing. The successful upload is recorded as the fifth non-dummy submission.
- Submission 6 scored **0.77990** on November 14 ([score evidence](assets/submission_06_score.png)): the compact-feature forest is a distinct ablation candidate (0.8244 CV accuracy). The original feature set remains best in development CV at 0.8329; removing separate family counts reduced validation accuracy. The CSV changes 2 labels from submission 4. The notebook explains the comparison and the retained model's grouped feature importance.

## Setup and execution

Use Python 3.13. The requirements pin the environment verified on macOS; other platforms may need compatible binary wheels.

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
jupyter lab titanic.ipynb
```

Select the environment's Python kernel and run all cells in order. To run the entire notebook in a fresh kernel without opening Jupyter:

```bash
.venv/bin/python scripts/run_notebook.py
.venv/bin/python -m unittest discover -s tests -v
```

The runner saves executed notebook outputs and a self-contained preview at `outputs/titanic.html`. It regenerates `submission.csv`, `submission_logistic_clean.csv`, `submission_forest_clean.csv`, `submission_03_gradient_boosting.csv`, `submission_04_random_forest_tuned.csv`, `submission_05_logistic_regularized.csv`, and `submission_06_feature_comparison.csv` in the repo root, plus experiment metadata at `outputs/experiment_03.json`, `outputs/experiment_04.json`, `outputs/experiment_05.json`, and `outputs/experiment_06.json`. Generated outputs are gitignored. The notebook includes all helper code and score screenshots; to run it elsewhere, provide only the two input CSVs and install the Python dependencies.

The original 80/20 holdout has already been examined, so it is a reused diagnostic. Model comparison uses identical stratified folds on the development portion. All learned preprocessing is fitted within each fold.

## Final submission files

The final notebook is `titanic.ipynb`. It includes saved outputs, all required project code, score evidence for six successful non-dummy submissions, a consolidated results table, overall conclusions, and proposed future work. The AI usage document remains a separate project-wide deliverable.

Build and verify the final handoff with:

```bash
.venv/bin/python scripts/build_final_submission.py
```

This runs the notebook in an isolated temporary directory containing only the notebook, `train.csv`, `test.csv`, `requirements.txt`, and the execution runner. No project helper modules or image assets are present. It verifies the inline definitions against the tested modules, executes every cell, checks that submissions 3–6 reproduce their recorded CSV hashes, and produces:

- `outputs/final_submission/titanic.ipynb` — executed final notebook, identical to the root notebook after the build.
- `outputs/final_submission/titanic.html` — self-contained reading preview.
- `outputs/kaggle_final_submission.zip` — notebook, HTML preview, input data, pinned requirements, and execution instructions.

Submit the `.ipynb` as the required report; the ZIP is a companion reproducibility bundle if additional files are accepted. These generated delivery files are gitignored and can be rebuilt. No Canvas submission is performed by these scripts.

## Conventions

- Keep generated files (`submission*.csv`, model artifacts, notebook checkpoints) out of git; the `.gitignore` already covers them.
- Put your own experiments in a notebook or script named after yourself or the approach so work doesn't collide.
