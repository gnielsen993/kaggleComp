Source: course instructions supplied by Gabe on November 14, 2026. Organized for reference with spelling and formatting cleaned up. The original pasted instructions did not include the destinations of the external links. Dates below are reproduced as provided; no additional deadlines are inferred.

## Kaggle competition project

### Team and competition selection

- Work in a team of up to two students.
- Each group participates in one Kaggle competition.
- Getting Started competitions (such as Spaceship Titanic) and Playground prediction competitions (such as San Francisco Crime Classification) are recommended.
- Mainly focus on tabular data analysis. Advanced competitions are also encouraged if the team feels comfortable.
- Competitions without specific evaluation metrics are not allowed, such as NFL Big Data Bowl 2026 Analytics.
- At most two teams can work on the same competition, to increase diversity in the selected competitions.
- Try several different methods to solve the problem. Methods do not have to be models taught in the course.
- Additional appropriate evaluation metrics may be used, but the competition's evaluation metric must be included.
- Team up with an LLM to complete the course project.

### Milestones and final delivery

| Deliverable | Weight | Requirements |
| --- | --- | --- |
| Project information | Not specified | Register for a Kaggle competition. |
| Checkpoint 1 | 15% | Download the data and run initial preprocessing. Make at least one dummy Kaggle submission (all-positive, all-negative, or most-frequent). Submit the Jupyter Notebook containing the code and a screenshot of the score on Canvas. |
| Checkpoint 2 | 15% | Do more preprocessing and make at least two non-dummy Kaggle submissions. Submit an updated Jupyter Notebook. |
| Final report | 35% | By this milestone, make at least six non-dummy Kaggle submissions. Submit a clean, runnable Jupyter Notebook as the final report, clearly explaining the preprocessing, feature engineering, and model experiments conducted. |
| Course project presentation | 35% | Present during the course presentation sessions. Cover both projects using the shared presentation guidance below. |

### Suggested Kaggle presentation content

The suggested structure is a starting point; sections and ordering may vary.

1. Overview of the competition and its overall objective.
2. Dataset and exploratory data analysis.
3. Data preprocessing and feature engineering.
4. Machine learning models, including dummy and non-dummy approaches tried.
5. Evaluation results.
6. Conclusion and future work.
7. How the team used an LLM in both the Kaggle and vibe coding projects.
8. Rules of thumb for vibe coding.

### Presentation grading

Peers will evaluate the presentations. The average evaluation will be the final grade from peers. Further details will be provided later.

## AI vibe coding project

### Project requirements

Use AI coding tools to design and build a complete machine learning project. The project must:

- Solve a clearly defined machine learning problem.
- Be a project other than another Kaggle competition. Identify the machine learning problem independently or with AI.
- Use AI coding tools as a meaningful part of the development process.
- Include testing or evaluation of the system.
- Be reproducible from the submitted repository.

### Deliverables

Each team must submit all three deliverables below.

#### GitHub repository

- Complete source code.
- A `README.md` with setup and execution instructions.

#### One-page project report

- Problem and motivation.
- System/design overview.
- How AI coding tools were used.
- Results and evaluation.
- Limitations and lessons learned.
- GitHub link to the project.

#### One-page AI usage summary

- AI tools used.
- Several representative prompts or interactions.
- Examples of AI-generated work that was modified, corrected, or rejected.

## Shared presentation instructions

- By default, the same group works together on both the Kaggle competition and the vibe coding project.
- Cover both projects during the presentation.
- Suggested timing: four minutes for Kaggle, four minutes for the vibe coding project, and two minutes for AI usage and rules of thumb.
- Spending more time discussing AI usage is acceptable.

## Using these requirements

These instructions describe course expectations, not verified completion status. Use them alongside the working notebook and submission evidence when planning remaining work. The supplied instructions do not specify a separate deadline or grading breakdown for the vibe coding deliverables.
